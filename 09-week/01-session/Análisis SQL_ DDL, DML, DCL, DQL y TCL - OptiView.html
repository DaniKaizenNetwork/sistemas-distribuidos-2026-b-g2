🎯 Principios de Arquitectura
Schema per Service: Cada microservicio tiene su propio schema. No hay JOINs cross-schema ni FKs entre schemas. Los datos se comparten vía REST APIs o eventos.
Migraciones Forward-Only: Una vez ejecutada en producción, una migración nunca se revierte. Los cambios incompatibles se hacen en dos fases: agregar columna nueva → drop columna vieja.
Soft Delete por Defecto: Los registros se marcan como eliminados (deleted_at = NOW()) en lugar de borrados físicamente. Preserva auditoría, cumple GDPR, evita problemas con FKs.
Transacciones Distribuidas (Saga + Outbox): Las operaciones que cruzan servicios usan Saga Pattern (compensating transactions) y Outbox Pattern (garantía de publicación de eventos).
Validación en Doble Capas: Reglas de negocio en la aplicación + constraints en la BD. La BD es la segunda línea de defensa.
