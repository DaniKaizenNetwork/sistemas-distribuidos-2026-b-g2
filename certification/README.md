## Skills summary

I completed the HCCDP-Solution Architectures course and applied its design techniques to OptiView, the distributed system my team built this semester. I learned to reason about a solution architecture through the five design principles — reliability, security, performance efficiency, cost and operations — and to state each decision as a trade-off instead of a preference.

I practised designing for failure: decoupling services so that one failing component does not take the request path down, and sizing scaling thresholds per service rather than for the system as a whole.

I also worked through disaster-recovery planning, choosing a recovery pattern from explicit RTO and RPO numbers instead of assuming a backup is enough.

In the labs I built and deployed cloud resources and saw how automated deployment and rollback change the risk of a release.

Applying this to OptiView, I used threat modelling (STRIDE) on the browser-to-API boundary and turned the findings into tracked security issues, which is the security principle in practice.
